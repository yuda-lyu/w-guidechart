Methods

(async) WGuidechart(conf, optopt) → {Promise}

Description:

  • 功能指引圖之取景、排版與繪製: 於網頁畫面之截圖上, 以紅框圈選各功能區, 以雙段灰色引線(斜線＋水平線)指至四周, 並於水平線上方寫功能文字

    流程: 檢測全部輸入(無效即 reject E_ARG, 無任何副作用) → 解析 opt.names → (未取景時先驗資料檔) → 建立輸出資料夾 → env.launchBrowser() → opt.capture 為 true 時逐圖取景(截圖不含紅框並量框, 寫 /shots/<名稱>.png、data/<名稱>.json) → 逐圖繪製(寫 svg/<名稱>.svg、/<名稱>.png、data/<名稱>.layout.json) → 關閉瀏覽器(恰一次, 含 reject 路徑)

    信任邊界: conf 為程式碼。env.launchBrowser、env.openPage、view.open、env.afterCapture 以使用端之權限於 Node 執行, find.fn 於被截圖之頁面內執行(經 Playwright 之 page.evaluate 序列化, 須自足, 參數經 find.arg 傳入); 套件不從資料檔或網路取得任何會被執行之內容, 不動態執行字串。瀏覽器由使用端注入(Playwright 相容之 Browser; Chromium 系須經 w-playwright 啟動), 套件執行期不依賴 playwright、w-playwright

    失敗通道: 一律 reject Error 並帶 code(E_ARG、E_VIEW_NOT_FOUND、E_BROWSER、E_OPEN、E_SETTLE、E_BOX_NOT_FOUND、E_NOT_CAPTURED、E_STALE、E_DATA、E_CROP、E_FS); 訊息為固定英文詞彙且只帶路徑索引(如 invalid conf.views[2].name: must be a safe file name …), 不回顯輸入值; 使用端回呼或瀏覽器之錯誤經 wsemi maskDiagErr 後掛為 cause。 排版之「問題」不 reject: 圖照常輸出, 問題列於 issues(使用端自行決定離開碼)

    輸入之種類(dspec〈輸入參數之檢測機制〉; 全表見 README 與 sgud/rule/rulebook.md 之 R-GC-ARG): conf 之必給鍵無效即 reject E_ARG; 選填鍵(含 style、layout、capture、功能區之覆寫、opt 各鍵)無效時視為未給、改用預設, opt.debug 為 true 時經 opt.funLog('warn', { msg }) 或 console.warn 警告(不含值)

    Unit Test: Github

Example
import wpw from 'w-playwright' //使用端自備(npm i w-playwright); 啟動瀏覽器一律經 w-playwright, 不直接用 playwright／playwright-core
import WGuidechart from 'w-guidechart'

let conf = {
    dirWork: './guide-work',
    env: { launchBrowser: () => wpw.launchChromium() },
    views: [{
        name: 'home',
        open: (page) => page.goto('http://localhost:8000/'),
        regions: [{ label: '查詢列', find: { sel: '.toolbar' } }],
    }],
}
let res = await WGuidechart(conf, { capture: true })
if (res.some((r) => r.issues.length > 0)) {
    process.exitCode = 1
}
